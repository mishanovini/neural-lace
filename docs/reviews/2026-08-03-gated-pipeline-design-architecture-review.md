## Verdict: SOUND-WITH-AMENDMENTS

**THE ONE THING: anchor the review chain in hook-observed facts, not self-declared prose.** Both chokepoints of the pipeline currently rest on self-attestation: G2 blocks only dispatches that *declare themselves* builders (`NL-ATTRIBUTION: role=builder` in the prompt), and a chain entry validates against a review record that *any session can write* — nothing checks that the named reviewer agent was ever dispatched. The proven failure mode this design exists to kill is a *sloppy, momentum-pressured session* (P-39), not a determined fabricator — and a sloppy session is exactly the one that omits the attribution line (→ G2 WARNs instead of blocking) or assembles a plausible record (→ P-30 recurs with one extra line of fiction). Two cheap amendments close this: **(a)** key G2 on `tool_input.subagent_type` — a fact the hook already sees and `model-pin-gate.sh` already blocks on (PROVEN: settings.json.template:332-358; workstreams-emit.sh:1953 fixtures show `subagent_type` in the event) — treating any build-category agent type (`plan-phase-builder`, `test-writer`) as a builder regardless of prose; **(b)** have the existing Task|Agent hook path append a dispatch-ledger row `{subagent_type, model, ts, session}` and have `review-chain-lib.sh` validate a chain entry only when a matching reviewer-dispatch row exists in the artifact's lifetime. With these, D-15.3's "IMPOSSIBLE" claim becomes true against the failure class that actually occurred, not only against the polite variant.

## PHASE 0 — my independent derivation (written from the inventory, handoffs, reviews, and code BEFORE reading the proposal in detail)

- **Real problem.** The pipeline design→plan→build→deploy has no mechanical connective tissue: reviews skippable (P-39/P-40 PROVEN), review-linked ≠ review-performed (P-30, Check 17 verified live at plan-reviewer.sh:3304-3393 — it greps a linked file for a verdict token), design authoring ungoverned (P-31; no authoring agent among the 25; model-policy.json pins design *review* only), directives in 7 stores with no identity or supersession (P-32/P-33), plus three open runtime defects (F1/F2 Criticals + F6 now-live) blocking maintenance activation, a 71-red unreadable arbiter, and the deferred anti-bloat stage.
- **Forces.** D-15 binding (reviewer per transition, world-class-at-one-job, skip impossible, complete set at deploy) · D-07 anti-bloat binding (inventory DOWN; this estate's signature failure is the additive reflex, P-37) · fidelity review is *semantic* — a grep-shaped script cannot judge whether a task substantively implements a REQ · gates must ride events hooks actually see (spawn tax 132–190 ms bounds per-event cost) · mechanism > memory: any chain link that works only if an actor *remembers* is already broken · the arbiter is currently unreadable, so new REDs are invisible.
- **Invariant (one sentence).** Every artifact that advances the pipeline must carry machine-verifiable proof — reviewer identity, verdict, and the bytes reviewed — grounded in facts the harness *observed* rather than facts the author *asserted*, and each stage must mechanically refuse input lacking it.
- **My candidate design (3 lines).** (1) Fix F1/F2/F6 + make the arbiter readable first. (2) One artifact-carried provenance chain (agent + verdict + blob sha), validated by a shared parser at three chokepoints — plan-write/commit, builder dispatch (keyed on subagent_type), and the existing pre-push funnel — cross-checked against a hook-written dispatch ledger. (3) Add exactly the agents no existing one can cover: an authoring role, and a semantic design→plan fidelity reviewer; extend everything else. **Sacrifices:** 2–4 premium-model reviews of latency/cost per pipeline traversal; a change-class taxonomy so small changes don't pay the full set; the chain machinery is itself new surface the doctor must verify.
- **DIVERGENCE FROM THE PROPOSAL.** The proposal converges with this derivation to a degree I rarely see — same problem, same mechanism class, same agent arithmetic, same phase-A-first. Four divergences, adjudicated below: the proposal grounds its gates in self-attestation where I ground them in hook-observed facts (**the proposal is wrong** — Finding H1); it asserts SHA-anchoring without specifying mismatch behavior (**wrong by omission** — H2); it sequences the 71-red triage after Phase B (**I am probably right, but it is arguable** — M1); and it defers Stage 2 a second time with no mechanical admission trigger (**wrong given P-37/P-38 are this estate's named signature failures** — M3).

## SCRUTINY OF THE THREE FLAGGED COMMITMENTS

**(a) DEC-1 — two new agents vs the master handoff §5's "extend, add only one." The design is right and the handoff was wrong, for three defensible reasons.** (1) D-15.1/.2 is binding operator language: *"a dedicated REVIEWER AGENT sits between every major step… a generalist reviewer… is not acceptable."* The handoff's proposal maps the design→plan review onto grep checks in plan-reviewer.sh — a shell script cannot judge whether a task's text *substantively implements* a REQ; it can only check fields exist. That under-delivers the directive it claims to satisfy. (2) The handoff's own rationale ("the failures were absent checks, not capacity") argues against a *wider fleet for parallelism* — Q-01's other branch — not against a fidelity agent; the design keeps the mechanical floor (Checks 20–22) *and* adds the semantic judge, which is the correct two-layer shape. (3) S-19a's rule ("create only where none owns") is satisfied: no agent owns design→plan (premise 5, PROVEN). Reversal cost is two file deletions. One caveat: Q-01/Q-08 were framed as *open operator questions*; deciding them is defensible under §3 (D-15's verbatim text effectively answers them, and the reversal is trivial) but DEC-1 should be flagged in the plan's decisions-for-operator-review list, not only in the design table.

**(b) The review-chain contract (§4) as connective tissue.** Right mechanism class — artifact-carried provenance validated at chokepoints beats both status quo (link-existence) and the alternatives (a central pipeline-state DB would be a new store of truth with its own drift class; the artifact itself carrying its authorization travels with cherry-picks for free). Single-writer analysis passes: the chain lives in the artifact it authorizes, one parser (`review-chain-lib.sh`) is the sole validity oracle, and it *derives* validity on read from the record files rather than maintaining state — no new drift class, PULL-classified on a cold path where pull is correct. The two structural holes are the trust root (H1) and the missing staleness contract on anchors (H2). Fix those and this is the right spine.

**(c) Phase sequencing.** A-before-everything is correct (a pipeline built on a wedged daemon and a corrupted arbiter cache would be theater — the design's own words, and true). B-before-C is defensible (B is the operator's central concern; C1 gates only Stage 2). Two flaws: C1's placement (M1) and Stage 2's untriggered second deferral (M3). Stage-2 deferral itself is *correct* — the arch review's drain-before-Stage-2 condition is honored — but an estate whose signature failure is "mechanism built, never armed" (P-38) should not leave its load-bearing anti-bloat stage with no date, no trigger, and no doctor visibility.

**P-42 discharge (§1) — scrutinized as directed: SOUND.** The design does the three things a sound discharge requires: it *drops* the refuted premise (Law 1 conflicts with push) explicitly, citing the operator's correction and the file's own text (derive-cache.js:7-11 — derive-from-oracle is the law; refresh-on-timer is line 11's implementation choice); it *re-derives* the register's justification on four independently PROVEN grounds (P-32 append-invisibility, P-33 seven stores, nl-issues 2026-08-02e carriage violated twice in one hour, P-38 no directive→mechanism state), each of which survives the refutation because none depends on the Law-1 conflation; and it *retains supersession* on the corrected framing (appended doctrine persists as live citations — REQ-B4 amends only the timer-refresh reading, correctly leaving derive-from-oracle standing). Residue: the inventory also directed that the predecessor's *other* findings "be re-audited for the same conflation." The design silently adopts F2/F6/F2b/invariant-8 without stating the re-audit. I performed it: those findings are measurement-anchored (71-red / 9m12s / class-count arithmetic / harness-doctor.sh:283-296), not Law-1-dependent — the adoption is safe, but the design should say one sentence to that effect (L2).

## FINDINGS (ranked; severity = blast-radius × likelihood × irreversibility)

**H1 [HIGH] [failure-mode-first + premise-testing] [design text PROVEN (§4 G2 spec, §4 parsing rules, §8.6); P-39-omits-attribution HYPOTHESIZED — refuter: P-39 transcript showing `role=builder` headers on the offending dispatches]**
Defect: both chain chokepoints trust self-attestation. G2's block condition requires the dispatch prompt to volunteer `NL-ATTRIBUTION: role=builder plan=<slug>`; absent that, the dispatch passes with a WARN — so the gate's guarantee is scoped to compliant actors, and the proven failure actor (a momentum-pressured session, P-39) is the least likely to comply. Likewise a chain entry validates against a record any session can author; the parse defeats the *honest* derived record (P-30 verbatim) but not the same record plus one false `Reviewer:` line. Failure scenario + what the user sees: builders build against an unreviewed plan again; the operator discovers a dropped requirement weeks later; the pipeline that promised "skip is IMPOSSIBLE" reads as having lied. Silent? Yes — a WARN in an unread channel; the system does not know. Required change (concrete): (1) G2 treats any dispatch whose `tool_input.subagent_type` is a build-category agent (per model-policy.json categories) as a builder dispatch — attribution prose refines (plan slug), never gates; block if the plan slug is underivable from prompt+attribution for a build-type spawn. (2) Extend the existing Task|Agent hook path (workstreams-emit already parses these events — anti-bloat: extend, don't add) to append `{subagent_type, model, ts, session_id}` to a dispatch ledger; `review-chain-lib.sh` validates a chain entry only if a reviewer-dispatch row for that agent exists within the artifact's lifetime. (3) Add both adversarial variants to REQ-B8's acceptance demo: a builder-type dispatch *without* attribution must block; a chain entry naming a never-dispatched reviewer must fail parse.

**H2 [HIGH] [derived-state discipline + staleness contract] [PROVEN by omission — no mismatch rule anywhere in §4/§6]**
Defect: `design-ref: <path>@<sha>` is claimed to make a chain entry "cover specific bytes," but no gate is specified to compare the current file's blob hash to the anchor, and no protocol exists for the *routine* mismatch: a SOUND-WITH-AMENDMENTS verdict obliges design edits (the no-addendum lint forces body integration), which changes the blob, which silently orphans the anchor. Same hole one stage down: a plan edited after plan-fidelity PASS (mid-build task-text tweaks pass plan-edit-validator) is built under a chain covering stale bytes. This is P-32's mutation-after-review class — the exact defect the chain exists to kill — reproduced inside the chain. What the user sees: a green chain over a design/plan that no longer says what was reviewed; wrong-and-silent, the worst rung. Required change: (a) G1/G2 compute `git hash-object` of the referenced artifact and compare to the anchor; mismatch ⇒ WARN during calibration, then BLOCK, with a named re-anchor path (the reviewer — and only the reviewer flow — re-anchors after folding amendments, or issues a delta-review record); (b) plan-reviews entries anchor the plan's blob too; G2 re-verifies at every dispatch; (c) state the staleness contract in §4 in one sentence: *no gate ever treats an anchored chain as covering bytes the anchor does not hash to.*

**M1 [MEDIUM] [Phase-1 measurement + the predecessor review's own F2a] [PROVEN — 71-red doctor per the evidence file; REQ-C1 sequenced after 12 Phase-B REQs]**
Defect: the 71-red triage (REQ-C1) runs after Phase B, so every Phase-B mechanism ships against an unreadable arbiter — new REDs (F4's zero-substrate flip, cadence REDs, any Phase-B manifest check) land invisible in the pile, and Phase-B done-bars that reference doctor state are degraded exactly as the predecessor review proved for Stages 0–1. The dispositions for C1 already exist (2026-08-02-estate-entropy-triage.md), so the cost of moving it is near zero. Required change: move REQ-C1 into Phase A (or run it as A-parallel); alternatively state explicitly that Phase-B done-bars use targeted self-tests, never global doctor state, until C1 lands — pick one, in the design body.

**M2 [MEDIUM] [hot-path cost model + workaround-as-sensor law] [HYPOTHESIZED — refuter: rrg_in_surface already exempting docs paths from G3's class computation, stated in the design]**
Defect: DEC-5's "docs-only → plan-fidelity only" class, computed from pushed paths, gates the pipeline's own exhaust: pushing a review record, a handoff, or backlog churn is a docs-only push that would demand a plan-fidelity review — circular (the record authorizing a push must itself be pushed) and a mass-FP generator whose predictable outcome is escape-hatch muscle memory, which D-04 defines as a defective gate. Required change: the DEC-5 config table gains an explicit exempt class (`docs/reviews/**`, `docs/handoffs/**`, `NEEDS-YOU.md`, backlog auto-churn) with the rationale line "the pipeline never gates its own provenance artifacts"; measure the class table against one week of real push history before the BLOCK flip date.

**M3 [MEDIUM] [anti-bloat scorecard + P-38 pattern] [PROVEN — §6 non-goals defers Stage 2 with no trigger; scorecard §7 concedes this cycle is net-additive again]**
Defect: Stage 2 (hooks-per-Bash 25→~5, the load-bearing anti-bloat stage) is deferred a second consecutive cycle with no date, no admission trigger, and no doctor visibility — in the estate whose named signature failure is mechanism-built-never-armed (P-38) and whose control system already became a failure cause (P-37). The predecessor pre-mortem's stall-at-Stage-2 trap is now one cycle closer to being the outcome. Required change: REQ-C1's completion mechanically opens Stage-2 admission — a register entry with an SLA, or a doctor WARN "stage-2 admission open since <date>" (data-file date, per the design's own F7 rule). One line of mechanism converts "next cycle" from intention to obligation.

## Steelman

- **The cheapest alternative** (master handoff §5: fix Criticals, extend plan-reviewer mechanically, add only design-author): saves one agent and one gate; satisfies the letter of "a check exists." It fails D-15.1's verbatim bar, cannot judge substance (a plan citing every REQ while implementing none passes greps), and would have to be rebuilt into the proposed shape the first time a semantic fidelity miss recurs. Rejected on the operator's own binding language, not on taste.
- **Doing nothing** (ship Phase A only): the Criticals get fixed, the machine stays calm — and P-29/P-30/P-39/P-40 remain open with four PROVEN recurrences already on the books. The problem is real, measured, and operator-named as the central concern. Rejected.
- **The design itself (strongest case):** it is the only proposal that makes D-15's acceptance bar *demonstrable*; every decision carries a reversal cost; every inventory item has a disposition (§9 is complete — I checked); the P-42 discharge is honest; the gates ride proven event surfaces; the anti-bloat ledger names displacements instead of asserting them. Its flaws are specification gaps at two joints, not a wrong shape.
- **THE CROSSOVER:** the design wins where change volume is real multi-task work and the actors are imperfect-but-not-adversarial — which is this estate. It loses if the trust roots stay self-attested (the guarantee evaporates exactly under the pressure that created P-39) or if per-change review cost is misfit to micro-changes (M2/L5 calibration). Both loss conditions are amendable, which is why this is SOUND-WITH-AMENDMENTS and not NEEDS-RESHAPING.

## What the current system gets right (and this design must not lose)

The push funnel as the authoritative layer with remedy-reachability reasoning (review-record-push-gate.sh header — the actor at push CAN dispatch reviewers; G3 extends rather than replaces this: correct); the builder-never-stranded property (commit-time advisory, NL-FINDING-016/019 traps preserved); the observe-first WARN-with-data-flip discipline (the design encodes the F7 lesson everywhere — keep it); model-pin-gate's block-on-unknown-type posture (the precedent H1's fix generalizes); plan-reviewer's mechanical floor at commit time (kept as Checks 20–22's substrate); and the evidence-file honesty culture — builders self-flagging gaps is constitution §1 working, and nothing in the new gate stack may punish a builder for declaring a gap (G2/G3 as specified do not; keep it that way).
