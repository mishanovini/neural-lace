# config-control-allowlist.txt — the ONE machine-readable ledger of config
# levers (env vars) that are legitimately consumed with ZERO in-repo
# producer, because the producer is external BY DESIGN: an operator's own
# shell, or a self-test/CLI-only override. Read by
# scripts/config-control-producer-scan.sh; an entry here is a documented
# claim, not a blanket suppression -- each row must cite where the lever
# is read and why no in-repo producer is expected.
#
# This is the allowlist half of the HARNESS-GAP-57 generalization: the
# registry-vs-callsite invariant (doctrine/vaporware-prevention-full.md)
# checks "does a registry entry have a consumer." This scan checks the
# missing other half for non-UI config levers: "does a consumed lever
# have a producer" -- and this file is where a deliberately
# producer-less lever gets to say so, on the record, instead of silently
# passing or silently blocking.
#
# ---------------------------------------------------------------------------
# FORMAT (parseable by bash 3.2 with `read -r var reason`)
# ---------------------------------------------------------------------------
#   <VAR_NAME><whitespace><reason, cites the read site and the intended
#   external producer (operator shell / self-test / power-user CLI)>
#
#   - `#` starts a comment; blank lines ignored.
#   - An entry here is ENFORCED-as-documentation, not enforced-as-code: if
#     the named var later gains a real in-repo producer, the scan
#     reclassifies it PRODUCED and the allowlist row becomes inert (safe to
#     delete on the next sweep, not a correctness bug either way).
#   - Do NOT add an entry to silence a var you have not read the callsite
#     for. Every row below was audited (2026-07-29, HARNESS-GAP-57
#     construction) against the actual read site before being added.
# ---------------------------------------------------------------------------
